# Architecture

> Generated by Codex on 2026-08-27

## Overview

This repository is Jitsi Meet: a multi-platform video conferencing client for web, Android, iOS, and SDK embedding. The app is primarily a React + Redux TypeScript application under `react/features/`, with a legacy JavaScript layer under `modules/` and root files such as `app.js` and `conference.js`.

At runtime, the browser app loads configuration from `config.js` / `interface_config.js`, initializes `lib-jitsi-meet`, creates or joins an XMPP-backed conference, and renders the meeting UI through React feature modules. React Native uses the same feature-oriented architecture where possible, with platform-specific source suffixes and Metro bundling.

## Feature Module Pattern

Feature directories commonly contain:

- `actionTypes.ts` for Redux constants
- `actions.ts`, often with `.any.ts`, `.web.ts`, or `.native.ts` variants
- `reducer.ts`
- `middleware.ts`
- `functions.ts` for selectors and helpers
- `constants.ts`
- `types.ts`
- `logger.ts`
- `components/`
- `components/web/` and `components/native/` when UI diverges by platform

New features should follow the existing `react/features/[feature-name]/` pattern and be imported into the appropriate app reducer/middleware registry file.

## Redux and State Architecture

Redux is registry-based:

- `react/features/base/redux/ReducerRegistry.ts` collects feature reducers.
- `react/features/base/redux/MiddlewareRegistry.ts` collects feature middleware.
- `react/features/base/redux/PersistenceRegistry.ts` persists selected state subtrees.
- `react/features/base/redux/StateListenerRegistry.ts` subscribes to derived state changes.
- `react/features/app/types.ts` defines `IReduxState` and the typed feature state map.
- `react/features/base/app/components/BaseApp.tsx` creates the Redux store from the registered reducers/middleware.

The app-level imports are side-effectful and important:

- `react/features/app/reducers.any.ts`
- `react/features/app/reducers.web.ts`
- `react/features/app/reducers.native.ts`
- `react/features/app/middlewares.any.ts`
- `react/features/app/middlewares.web.ts`
- `react/features/app/middlewares.native.ts`

If a reducer or middleware is created but not imported in the appropriate platform file, it will not run.

## Conference Lifecycle

The core conference flow spans both old and new layers:

1. Web app bootstraps through `app.js`.
2. Config is loaded into `features/base/config`.
3. `lib-jitsi-meet` is initialized through `react/features/base/lib-jitsi-meet`.
4. Connection is created in `react/features/base/connection/actions.any.ts`.
5. Conference join/lifecycle events are handled by `react/features/base/conference/actions.any.ts`, reducers, and middleware.
6. Web-specific lifecycle and media control still heavily uses `conference.js` and `APP.conference`.
7. Tracks are created and managed by `react/features/base/tracks/*`, with web/native implementations.
8. UI features react to Redux state and conference events.

Important caution: many web flows still bridge through global `APP`, especially `conference.js`, `modules/UI`, and media/track middleware. Refactors here should be narrow and tested.

## Platform Strategy

The repo uses platform-specific suffixes:

- `.web.ts` / `.web.tsx` for browser code
- `.native.ts` / `.native.tsx` for React Native code
- `.any.ts` / `.any.tsx` for shared logic
- `.android.ts` / `.ios.ts` for mobile platform-specific implementations

`tsconfig.web.json` uses `moduleSuffixes: [".web", ""]` and excludes native/mobile paths. `tsconfig.native.json` uses `moduleSuffixes: [".native", ".ios", ".android", ""]` and excludes web-only features.

## Conventions

- Prefer TypeScript for new/changed React feature code.
- Respect platform suffixes and keep web/native divergences explicit.
- Register feature state through registry imports, not central reducer composition.
- Avoid adding `index` files unless matching an existing pattern.
- Feature logging typically uses a local `logger.ts`.
- Existing repo guidance expects `npm run lint:ci` and `npm run tsc:ci` before commits.
- Conventional commits with scopes are documented in `CLAUDE.md` / local GSD rules.

## Technical Debt / Risk Areas

- Legacy global `APP` and `conference.js` still own substantial web conference behavior.
- `modules/UI` and React feature UI overlap, especially around video layout and Etherpad.
- `config.js` and `interface_config.js` contain many deprecated options for backward compatibility.
- Some state ownership is acknowledged as imperfect in comments, especially media/config/conference interaction.
- Web device selection and track control still have comments noting behavior outside pure Redux.
- `static/login.html` has a hardcoded Google OAuth client ID in local custom work.
- `node_modules/` is present in the repo workspace and should generally be excluded from searches/build artifacts.
- The worktree is dirty; future edits should preserve existing local changes.

## Practical Navigation Guide

When changing a feature:

1. Start in `react/features/[feature]/`.
2. Check for `.any`, `.web`, `.native`, `.ios`, `.android` variants.
3. Check whether reducer/middleware registration imports are needed in `react/features/app/`.
4. If the behavior touches conference join, tracks, devices, or hangup, inspect both the React feature and `conference.js`.
5. For iframe/API behavior, inspect both `modules/API` and `react/features/external-api`.
6. For UI tests, look for matching specs in `tests/specs/` and page objects in `tests/pageobjects/`.
